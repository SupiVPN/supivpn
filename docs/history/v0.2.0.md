# SupiVPN v0.2.0

Changes since [v0.1.1](v0.1.1.md).

## Changes

- Add structured JSON logging and bounded file retention

## Compatibility

These notes summarize commit subjects; they do not assert runtime or migration compatibility. Review configuration and migration changes before upgrading. The Release page reports schema compatibility from the verified package manifests.

## Logging features

- Structured JSON application events for the VPN agent, VM controller, public/agent/recovery Lambdas and command-line utilities. Events include UTC timestamps, schema version, component and stable event names.
- Tunnel events include the verified username, selected group and assigned address. Sensitive payloads, credentials and raw authentication responses are excluded; user-controlled text is escaped.
- Configurable file, stderr or stdout output. VM defaults are `/var/log/supivpn/agent.jsonl` and `/var/log/supivpn/controller.jsonl`; Lambda and CLI logs use stderr.
- Application-managed file rotation with configurable retention: 7 days, 10 MiB per file and 10 archives by default. Runtime output failures switch application events to stderr and emit `logging.output_failed`.
- File ownership, permissions, symlink/hardlink checks and an exclusive writer lock protect local log output. Successful heartbeat/fetch operations do not produce a log for every request.

## Upgrade requirements

- **Before starting the new VM binaries, create the log directory owned by the service UID with mode 0750 or 0700 and allow it in the service sandbox.** Alternatively, explicitly configure `"logging":{"output":"stderr"}`. Unsafe or unavailable file output fails startup.
- Collect JSON files and rotated archives with rename-aware checkpoints, plus the service journal for startup errors and fallback. Collect each Lambda's CloudWatch Logs group separately. Native OpenVPN and DNS logs remain separate text streams. No S3 uploader or application-side network exporter is included.
- Local file retention does not configure CloudWatch, journald or collector retention. Archive age is based on its last write; this is not exact per-record expiry or a lossless audit ledger.
- Update text-based log filters and any scripts matching migrator/profile success text. CLI completion messages now use stderr JSON; exit codes and operator JSON stdout are unchanged.
- Database schema remains 9 and bundle format remains 3. No database migration is introduced. Rollback must restore the matching older configuration as well as binaries because older binaries reject the new `logging` field.
- Configuration and collection reference: [LOGGING.md](../LOGGING.md).

## Validation

Local unit/race, vet, PostgreSQL 18 integration, source audits and OpenVPN 2.7.8 ARM64/AMD64 integration checks passed. Linux logging tests cover rotation, retention, file safety and stderr fallback. Release publication also requires the successful protected-main verification and integration pipeline for the exact signed tag commit.

## Package compatibility

- Targets: `linux-arm64` (primary), `linux-amd64`
- Bundle format: `3`
- Database schema: `9`; compatible VM schemas: 7, 8, 9
- Public, agent and recovery Lambdas require schema `9`, separate roles and a controlled cutover from the combined Lambda.
