# SupiVPN v0.5.0

## Changes

- Consolidate authorization guards, strict JSON parsing, SAML XML helpers,
  profile validation and release checksum handling without new dependencies.
- Allow profile downloads with an explicitly unlimited session policy, while
  retaining signed IdP session limits, login expiry and one-use replay protection.
- Check node lease expiry after acquiring the heartbeat row lock. A heartbeat
  delayed past its lease cannot renew the expired generation.
- Reduce database round trips for heartbeat and authenticated decision operations.
  Use existing expiry indexes to bound cleanup scans, preserving active grants,
  batch limits and recovery history retention.

## Compatibility

Database schema is **10**; bundle format **3**, configuration formats and JSON
log schema **1** are unchanged. VM components support schemas 7, 8, 9 and 10.
All isolated Lambda components require schema 10 and their existing restricted
database roles. No additional runtime privileges are needed.

Migration 010 replaces heartbeat and cleanup functions. It preserves data and
existing function ownership/ACLs, performs no table rewrite or index build, and
uses the existing bounded migration timeouts. Earlier migrations are unchanged.

For VM deployments, install this runtime on the existing supported schema before
applying migration 010. For isolated Lambdas, quiesce old integrations and the
recovery schedule, apply the migration, deploy all matching bundles and verify
the boundaries before resuming traffic. Drain/stop VPN pairs through maintenance
if heartbeat continuity cannot be maintained; clients will need to reconnect.
See [upgrade instructions](../POSTGRES.md#schema-9-to-10) and the
[Lambda cutover procedure](../LAMBDA_ISOLATION.md#upgrade-and-rollback).

This is the first runtime supporting schema 10. After migration, v0.4.5 and older
bundles are not rollback targets: restore only a verified schema-10-compatible
runtime. Keep committed schema/data; do not remove migration metadata, reverse
DDL or restore an older database snapshot to roll back the application.
