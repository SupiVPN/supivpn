# SupiVPN v0.9.1

## Changes

- Restore explicit acceptance of existing unbound profiles for the remainder of
  v0.9.x, correcting their premature removal in v0.9.0. Final removal is v0.10.0.
- Require both a separate `profile_binding: "legacy"` agent/metadata gate and an
  exact `legacy_profile_nodes` allowlist on the controller. Public and agent
  Lambdas use the same allowlist. Emit warnings at startup and legacy admission.
- Preserve all bound-profile proof, owner and active/blocked checks, including
  on UDP and optional TCP. New downloads remain bound-only.

## Compatibility

Binding and deprecation began in v0.8.0; v0.9.x is the last compatible series.
Omitted agent mode remains `required`, and the allowlist defaults to empty.
The exception is opt-in and does not weaken existing v0.9.0 defaults. Historical
keys work only on their separate legacy UDP listener; malformed/new-format
credentials and infrastructure errors never trigger fallback. Legacy users do
not receive the owner-binding guarantee and must download a bound replacement
before upgrading to v0.10.0. Blocking a bound profile does not revoke an old key.

Schema remains 12; no database migration, key rotation or reissue of existing
bound UDP-only/dual-transport profiles is needed. Upgrade agents and controllers
together; arbitrary mixed versions are unsupported. Legacy mode requires the
PostgreSQL-backed controller and does not restore the embedded controller.
The setup helper remains bound-only. See the [migration and rollback procedure](../PROFILE_BINDING.md#explicit-legacy-transition-through-v09x).

Tests cover default refusal, explicit legacy admission, SAML/group checks,
cross-format rejection, policy removal before completion/fetch/ACK, session
limits across formats, and combined/isolated database roles. Native Connect and
live AWS deployment are separate acceptance checks.
