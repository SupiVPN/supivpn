# SupiVPN v0.10.0

## Changes

- Add essential Prometheus-format metrics without new dependencies. Metrics are
  disabled by default and enabled explicitly in configuration. VM components
  use a separate TLS listener; public Lambda requires a dedicated Bearer token
  loaded from Secrets Manager. Collection has bounded work, timeouts and caching.
  See [metrics configuration](../METRICS.md).
- Finish the profile migration announced in v0.8.0: remove unbound admission,
  the legacy agent/metadata mode and controller node allowlist. Both VM and
  Lambda enforce active profile proof and verified SAML ownership. Historical
  unbound logins cannot complete authorization, deliver a grant or acknowledge
  it after the upgrade.
- Remove offline unbound issuance through `supivpn-profile -out`/`-template`.
  Wrapping-key initialization with `-init` remains supported; obtain client
  profiles through SAML-authorized download or OpenVPN Connect import.
- Update the pinned Pages upload/deploy actions to native Node.js 24 versions,
  keeping the signing, artifact checks and publication gates unchanged.

## Compatibility

**Breaking for unbound users:** v0.8.x and v0.9.x were the migration window;
v0.9.1+ is the last compatible series with the explicit legacy listener.
Complete migration there before installing v0.10.0. Download bound replacements
through SAML, verify them, drain/stop legacy agents and OpenVPN listeners, and
close their old ports/routes. Remove `legacy_profile_nodes` from every combined,
public and agent controller configuration, even if empty or null. Old legacy
configuration now fails validation instead of silently enabling weaker access.
See [upgrade and rollback](../PROFILE_BINDING.md#explicit-legacy-transition-through-v09x).

Schema remains 12 with the same runtime grants. No database migration or
reissue of existing bound profiles is needed. Preserve wrapping keys, TLS trust
and existing bound endpoint/ports. Bound UDP-only and UDP/TCP profiles remain
supported; TCP and metrics are disabled by default. OpenVPN is unmodified.

Upgrade controller/Lambda and node binaries together in a maintenance window;
mixed v0.9/v0.10 server components are not a supported rolling-upgrade matrix.
A Lambda update alone does not stop an existing unbound tunnel. Preserve
revocations, replay history and node generations; do not delete live login rows
or down-migrate the database. Rollback requires a tested, matching schema-12
server pair and saved configuration. Re-enabling v0.9.x legacy mode restores
its old profile-sharing/relay risk.

VM metrics intentionally have TLS without application authentication in the
minimal deployment; restrict reachability to monitoring hosts. Lambda metrics
require separate route, IAM/KMS and token configuration. Native Connect,
live AWS metrics deployment and a full Debian VM metrics acceptance run remain
deployment acceptance checks; do not infer them from unit or container tests.
